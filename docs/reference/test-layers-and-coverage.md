# Test layers and coverage

## Layers

| Layer       | Where the tests are                                                      | Needs                                   | Runs in                                       |
| ----------- | ------------------------------------------------------------------------ | --------------------------------------- | --------------------------------------------- |
| Unit        | `apps/<app>/src/**/*_tests.ts(x)` and `apps/<app>/src/bdd/*_tests.ts(x)` | nothing                                 | `test:unit`, `test:quick`, pre-push           |
| Integration | `apps/<app>/src/**/*_integration_tests.ts(x)`                            | the dev stack (`npx nx db:up flash-be`) | `test:integration`, `test:coverage`, pre-push |
| End-to-end  | `apps/<app>-e2e/steps/*.steps.ts` and the Playwright specs               | the dev stack and the apps              | `test:e2e`                                    |

The pre-push hook runs the combined coverage gate, so integration tests run there too. `test:coverage` starts the dev
stack itself. End-to-end tests are never part of the hooks.

## Nx targets

| Target             | App                             | What it runs                                                 |
| ------------------ | ------------------------------- | ------------------------------------------------------------ |
| `typecheck`        | every app                       | `tsc --noEmit` with the strict flags in each `tsconfig.json` |
| `lint`             | every app                       | Biome, and warnings fail the run                             |
| `test:unit`        | `flash-be`, `flash-web`         | unit tests with a coverage report (no floor)                 |
| `test:unit:watch`  | `flash-be`, `flash-web`         | unit tests in watch mode, no coverage                        |
| `test:integration` | `flash-be`, `flash-web`         | integration tests                                            |
| `test:coverage`    | `flash-be`, `flash-web`         | unit and integration together, with the 99% floor            |
| `test:quick`       | every app                       | `typecheck`, `lint`, and `test:unit`                         |
| `test:e2e`         | `flash-be-e2e`, `flash-web-e2e` | Playwright, built from the feature files                     |

Run a target with `npx nx <target> <app>`, for example `npx nx test:coverage flash-be`.

## Coverage floor

The 99% floor is on the combined run: unit and integration tests together. It covers lines, statements, functions,
and branches. The gate is `npx nx test:coverage <app>`. It starts the dev stack, and the pre-push hook runs it for the
affected apps.

Unit tests alone do not reach 99% for `flash-be`, because the database code is covered by integration tests. So
`test:unit` reports coverage without a floor.

Excluded from the coverage denominator:

| Path                                                       | Reason                                                               |
| ---------------------------------------------------------- | -------------------------------------------------------------------- |
| `*_tests.ts(x)`, `*_integration_tests.ts(x)`, `src/bdd/**` | test code is not product code                                        |
| `src/routeTree.gen.ts` (`flash-web`)                       | generated by TanStack Router                                         |
| `src/main.ts` (`flash-be`)                                 | process entry point; the end-to-end suite starts and calls it        |
| `src/migrate.ts` (`flash-be`)                              | process entry point; the migrator it calls is covered by integration |

## Behaviour coverage

Every scenario in `specs/` must be bound at the unit layer. It must also be bound at the integration and end-to-end
layers, unless it carries an exemption tag. `npm run bdd:check` checks this without running any tests. It fails when:

- a scenario has no unit binding, or a binding names no scenario;
- an exemption tag has no comment directly above it, or the comment is malformed;
- the alternative proof names a scenario that is not bound at its layer;
- an end-to-end step matches no step definition, or a step definition matches no step;
- a feature file is not linked from the `README.md` in its folder;
- a scenario title is built at run time, so the check cannot read it.

The check writes `generated-reports/behaviour-status.md`. Run it with `npm run bdd:check`. The rules above are specified
in [`specs/tooling/bdd-check`](../../specs/tooling/bdd-check/README.md).

The check's own rules are bound at every layer, with no exemptions:

- unit and integration: `npm run bdd:check:test` (Vitest, `scripts/bdd/*_tests.mjs`);
- end-to-end: `npm run bdd:e2e` (playwright-bdd, `scripts/bdd/e2e/steps`), which runs the checker as shipped.

## Exemption tags

| Tag                   | Meaning                                           |
| --------------------- | ------------------------------------------------- |
| `@integration-exempt` | the integration layer does not bind this scenario |
| `@e2e-exempt`         | the end-to-end layer does not bind this scenario  |

Each tag needs the comment described in [how-to: add a behaviour](../how-to/add-a-behaviour.md#5-exempt-a-layer-only-with-a-reason).

## Pre-push hook

`git push` runs, in order:

1. `npm run docs:check` (RHINO: links, heading structure, README indexes, Mermaid diagrams)
2. `npm run bdd:check:test` and `npm run bdd:check` (the behaviour check)
3. `npx nx affected -t test:quick --base=origin/main`

Integration and end-to-end tests are not in the hook. Run them yourself before you finish a change.
